## Integration style
- **Merge mode:** squash (linear `main`, every subject ends in `(#N)`)
- **PR title convention:** Conventional Commits `<type>(scope): subject` — the PR title *is* the
  commit release-please parses, and `scripts/release-title-gate.sh` + the `title-gate` workflow gate
  it. Full landed shape is `<type>(scope): subject (#issue) (#PR)` — the issue number is carried in
  the title and the squash appends the PR number, e.g.
  `ci(workflows): give the release-title gate its own workflow (#57) (#119)`.
  Derive the type from the issue label (`bug`→`fix`, `enhancement`→`feat`); a docs-only or CI-only
  change uses `docs:`/`ci:`. A skills change must land with a *releasable* title (that was #27).
- **Branch naming:** `<type>/<issue>-<slug>` — e.g. `fix/50-dashboard-coverage`,
  `feat/70-if-gated-bundle-step`, `ci/66-renovate-config-validator`, `refactor/72-shared-test-preamble`.

## Conflict hot-spots (merge-with-main resolutions)
| File | Why it collides | Resolution |
|------|-----------------|------------|
| `CHANGELOG.md` | release-please regenerates it; every branch appends | **never hand-merge or hand-edit** — take `main`'s copy and let release-please rewrite |
| `.claude-plugin/plugin.json` (`version`), `.release-please-manifest.json` | release-please bumps them together | take **main's**; never bump by hand |
| `requirements.json` | the single source of truth for prerequisites — parallel features each add an entry | **union** the arrays; keep it the only place a prerequisite is listed |
| `.github/workflows/ci.yml` | every new suite wires itself in | **union** the steps — keep BOTH sides' registrations — then re-run `python3 scripts/ci-wiring-check.py` |
| `scripts/ci-wiring-check.py` | suites register themselves here too | **union**, same rule as `ci.yml`: dropping the other branch's registration silently un-gates its suite |
| `tests/_lib.sh` | the one home for the shared trap/scratch preamble | **understand both intents** — a careless merge here silently greens failing suites |
| `README.md`, `docs/`, `ARCHITECTURE.md` | parallel features document themselves | **union** |
| `tests/*/test.sh` | both sides append cases | **union** |
| `.claude/skills/repo-profile.md` (this file) | two branches re-detect it | **union** the sections; regenerate from the **main working tree** if they really diverge |
- **Rule of thumb:** union additive files, regenerate derived files, take-the-higher for the version;
  same-logic-both-sides is a real semantic conflict — understand both intents or stop.

## Architecture grain / invariants (shape implementation plans to these)
- **`requirements.json` is the single source of truth for prerequisites.** Add or remove a
  prerequisite *there*, never in a hard-coded list; `scripts/preflight.sh` and the skills read it.
  Its `level` is the pipeline gate (`required` = phase-0 hard fail, `recommended` = documented
  degradation), and `token` is the string `tests/skills/check-frontmatter.py` expects.
- **Gate discipline:** a failed gate stops forward progress — fix or roll back, never skip.
- **One home per shared mechanism.** `tests/_lib.sh` holds the scratch/cleanup preamble precisely
  because ten copies had already diverged (#72); in its trap handler `local rc=$?` must be the FIRST
  statement or a failing suite reports green. Same rule shape as `tests/_lib/py_module.py` for the
  python loader and `skills/implement-issue/scripts/_assert-branch.sh` for the git guards.
- **A tool the kit ships is a tool the kit tests** — every script under `scripts/` and
  `skills/*/scripts/` has a golden suite under `tests/<name>/test.sh`, and
  `scripts/ci-wiring-check.py` fails if a suite is not wired into CI.
- **Every suite must parse under macOS bash 3.2** — `./scripts/parse-sweep.sh` (#131).
- **`samples/` is frozen.** Suites assert its immutability and Renovate is scoped away from it.
- **A skills change must ship as a releasable PR title**, or the plugin never reaches consumers.
- **This profile is committed** (#157): the lifecycle skills read it through
  `skills/get-repo-profile/scripts/repo-profile.sh show`, which prints `NO_PROFILE` and exits 3 when
  it is absent, and `tests/repo-profile/test.sh` asserts this repo tracks its own.

## Environment gotchas
- **Branch protection is disabled** on `main` (the API answers `404 Branch not protected`). Nothing
  server-side blocks a bad merge, so the local CI gates above are the only real gate — treat them as
  mandatory rather than advisory. If protection is ever enabled it must require **both** check-runs,
  `kit` and `title-gate` (see the note in `.github/workflows/release-title.yml`).
- **No aggregate test runner.** Don't reach for a `make test`; run suites individually, which is also
  the fast per-task path.
- Use `git -C <path>`, not `cd`, when driving this repo from another working directory.
- `gh` needs `--repo phmatray/ai-migration-kit` when invoked from outside the clone; note the flag is
  `--repo`/`-R` on `issue`/`pr` but **not** on `gh repo view`, which takes the slug positionally.
- Raw `git fetch`/`push` can be sandbox-blocked while `gh` works (`port 443` refused) — re-run those
  with the sandbox disabled; local git needs no network.
